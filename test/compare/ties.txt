# Cases where GTS chooses between equal candidates by the order of its hash
# tables, which follows memory addresses. The C library gives different
# results from run to run on these cases without "setarch -R", and the C++
# library chooses by index or, for coarsening, by edge_order_key(). compare.py
# does not count their summaries as differences; compare.sh instead checks
# that the two surfaces are within MAX_DISTANCE of each other both ways
# (gts_surface_distance), a tenth of the mean edge length of the result.
#
# Each line is: NAME  MAX_DISTANCE  [KEY ...], where the summary lines KEY
# must agree all the same.

coarsen-sphere5-volume-number-1000      0.02
coarsen-iso-torus-length-cost-0.0625    0.008
coarsen-iso-torus-length-then-angle     0.008

# All edges of a cube have the same length; both results are triangulations
# of the cube.
refine-cube-length-number-200           1e-12

# The boolean cases below have no exact degeneracy, but the faces cut by the
# intersection curve are triangulated by ear clipping from the start of
# lists whose order follows GTS's bounding-box tree, which GTS builds in the
# order of its face hash table. The same polygons get different diagonals:
# 5 faces of a few thousand differ, and every vertex agrees.
bool-inter-horse5-horse6                0.0006
bool-diff-horse5-horse6                 0.0006

# The cluster grid makes its vertices and faces in the order of hash tables
# keyed by pointer, and sums the points of a cluster in that order. The two
# surfaces coincide; quads are split along the other diagonal, and the
# positions differ in the last bits, which the 10 digits of a written
# surface can round apart.
cluster-cylinder-1                      3.0
cluster-horse5-0.005                    0.0006
